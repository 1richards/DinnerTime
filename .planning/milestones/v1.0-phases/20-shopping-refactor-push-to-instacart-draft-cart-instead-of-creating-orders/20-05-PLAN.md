```yaml
#   - Tap "View shopping list" (secondary) → sheet dismisses, back on shopping list
#   - Tap "Order on Instacart" again
#   - Tap "Open in Instacart" (primary) → sheet dismisses (simulator opens Safari, acceptable)
#
# What this flow does NOT verify (deferred to DEVICE-TEST-20 on a physical iPhone):
#   - Universal link opens the actual Instacart app
#   - Items appear as drafts in the real Instacart cart
#   - Network-error variant (requires airplane mode)
#   - Auth-error variant (requires expired token)
#
# Screenshots produced (5):
#   29-01-shopping-list-ready       — shopping list with items before tap
#   29-02-handoff-sending           — HandoffSheet in sending state (if race allows)
#   29-03-handoff-success           — HandoffSheet in success state with CTAs
#   29-04-sheet-dismissed           — back on shopping list after dismiss
#   29-05-reopen-success            — sheet reopened with success
#
# Selector caveats (CLAUDE.md UAT section):
#   - "Sending to Instacart cart…" contains `…` — use regex .*Sending to Instacart cart.* (truncate the ellipsis)
#   - "{N} items ready" — use .*items ready.* (regex)
#   - "Open in Instacart" is a Button label — tap by exact text
#   - HandoffSheet close button accessibilityLabel="Dismiss"
---
- launchApp:
    clearState: true

- runFlow: _ensure-logged-in.yaml

# 1. Shopping tab — ensure we have a shopping list. If there's no list, generate
#    from a meal plan; else proceed.
- tapOn:
    text: ".*Shopping.*"
- extendedWaitUntil:
    visible:
      text: "Order on Instacart"
    timeout: 15000
    # If the button isn't visible, the list is empty. Flow 11 regenerates it.

- takeScreenshot: 29-01-shopping-list-ready

# 2. Tap "Order on Instacart" — triggers handleOrder → HandoffSheet sending.
- tapOn:
    text: "Order on Instacart"

# 3. HandoffSheet sending state (may be quick if stub Instacart returns fast)
- extendedWaitUntil:
    visible:
      text: ".*Sending to Instacart cart.*|.*items ready.*"
    timeout: 5000

# 4. Catch success state — tolerate either arrival order (sending may be <300ms).
- extendedWaitUntil:
    visible:
      text: ".*items ready.*"
    timeout: 10000

- takeScreenshot: 29-03-handoff-success

- assertVisible:
    text: "Open in Instacart"
- assertVisible:
    text: "View shopping list"

# 5. Tap secondary "View shopping list" → dismiss sheet without opening Instacart.
- tapOn:
    text: "View shopping list"

# 6. Sheet dismissed, we're back on the Shopping tab list.
- extendedWaitUntil:
    visible:
      text: "Order on Instacart"
    timeout: 5000

- takeScreenshot: 29-04-sheet-dismissed

# 7. Re-tap Order → success again → primary CTA.
- tapOn:
    text: "Order on Instacart"
- extendedWaitUntil:
    visible:
      text: ".*items ready.*"
    timeout: 10000

- takeScreenshot: 29-05-reopen-success

# 8. Tap "Open in Instacart" — simulator may attempt to open a URL scheme.
#    On the simulator this either opens Safari (universal link fallback) or
#    no-ops. Either way, the sheet state should resolve back to idle.
- tapOn:
    text: "Open in Instacart"

# 9. Return to app. Can't assert Instacart state in a real sense on the
#    simulator — just verify we're not stuck on an error state.
- runFlow:
    commands:
      - assertNotVisible:
          text: ".*trouble.*"
      - assertNotVisible:
          text: ".*Try again.*"
```

Notes on selector robustness:
- `text:` is regex; the `…` character is tolerated by `.*` wildcards on both sides.
- Secondary assertion ("View shopping list") uses exact-text match which Maestro treats as regex-but-literal-safe for simple strings (no `.`, `(`, `?`).
- If the sending state is too fast to catch reliably (< 500ms), skip asserting it explicitly — the success assertion covers the state transition outcome.
