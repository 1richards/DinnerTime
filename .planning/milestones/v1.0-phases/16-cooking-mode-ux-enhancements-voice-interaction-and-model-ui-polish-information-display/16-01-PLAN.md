  <behavior>
    The Wave 0 test (apps/mobile/src/cooking/__tests__/telemetry.test.ts) defines these exact contracts — this task makes them green:
    - `logCookingEvent({ session_id, event_type, recipe_id?, step_index?, payload })` enqueues. After 10 events → auto-flush (fetch called POST /api/v1/telemetry/cooking with Authorization header from `supabase.auth.getSession()`).
    - Timer-based flush: 1 event enqueued + 30s elapsed → flush fires.
    - `flushTelemetry()` callable directly; idempotent if queue empty.
    - 5xx failure: batch re-queued on `fetch` throw or non-ok status; next flush retries.
    - Auth missing (`supabase.auth.getSession()` returns null): events re-queued (don't drop).
    - Queue cap: enqueueing beyond 200 drops OLDEST events; queue.length stays ≤ 200.
    - `__resetForTests()` clears queue + any pending flushTimer — used by tests only.
    - Event payload surface: module does NOT log raw transcript text — callers pass structured payloads only. Module adds `client_ts: new Date().toISOString()` to each event.

    Note: No retry-with-backoff; mirrors offlineQueue pattern from Phase 10-04 (best-effort, drop-on-fail beyond one re-queue).
  </behavior>
  <action>
    Implements Pattern 1 (16-RESEARCH.md lines 229-273). Create `apps/mobile/src/cooking/telemetry.ts` with:

    1. Types:
       ```typescript
       export type CookingEventType =
         | 'stt_final' | 'stt_error' | 'intent_routed'
         | 'ask_start' | 'ask_first_chunk' | 'ask_complete'
         | 'tts_echo_swallowed' | 'command_unrecognized';

       interface QueuedEvent {
         session_id: string;
         event_type: CookingEventType;
         recipe_id: string | null;
         step_index: number | null;
         payload: Record<string, unknown>;
         client_ts: string;
       }
       ```

    2. Module-level state:
       - `const queue: QueuedEvent[] = [];`
       - `let flushTimer: ReturnType<typeof setTimeout> | null = null;`
       - `const QUEUE_CAP = 200;`
       - `const BATCH_SIZE = 10;`
       - `const FLUSH_INTERVAL_MS = 30_000;`

    3. `logCookingEvent(e: Omit<QueuedEvent, 'client_ts'>)`:
       - Push `{ ...e, client_ts: new Date().toISOString() }`.
       - If queue.length > QUEUE_CAP, drop oldest: `queue.splice(0, queue.length - QUEUE_CAP)`.
       - If queue.length >= BATCH_SIZE → `void flushTelemetry()`.
       - Else if !flushTimer → `flushTimer = setTimeout(() => { flushTimer = null; void flushTelemetry(); }, FLUSH_INTERVAL_MS)`.

    4. `flushTelemetry()`:
       - Clear flushTimer.
       - If queue empty, return.
       - `const batch = queue.splice(0, queue.length);`
       - Get session via `await supabase.auth.getSession()`. If no session → re-queue: `queue.unshift(...batch)`; return.
       - Try `fetch(`${process.env.EXPO_PUBLIC_API_URL}/api/v1/telemetry/cooking`, { method: 'POST', headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${session.access_token}` }, body: JSON.stringify({ events: batch }) })`.
       - On non-ok response or catch: re-queue: `queue.unshift(...batch)`.

    5. `__resetForTests()` (only exported under NODE_ENV check or dev flag — simpler: just export unconditionally, documented as test-only): clears queue + flushTimer.

    Per 16-RESEARCH.md Anti-pattern: do NOT log PII. This module does not enforce that — caller (hooks added in 16-06) is responsible. Add a one-line JSDoc on `logCookingEvent`: "@param e.payload must not contain raw transcript text. Callers sanitize upstream."
