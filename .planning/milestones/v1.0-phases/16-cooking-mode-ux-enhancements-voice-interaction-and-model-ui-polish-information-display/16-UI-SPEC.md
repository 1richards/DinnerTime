## Spacing Scale

Phase 19 8pt grid is authoritative. Declared tokens (all multiples of 4, from
the standard {4, 8, 16, 24, 32, 48, 64} set):

| Token (Tailwind) | Value | Usage in cooking mode |
|-------|-------|-------|
| `p-1` / gap-1 | 4px | Icon-to-text gap inside toasts and chips |
| `p-2` / gap-2 | 8px | Timer chip internal padding; waveform-bar gaps |
| `p-4` | 16px | Recipe horizontal gutter, step-card padding, ingredient-row vertical padding |
| `p-6` | 24px | Section break between Ingredients and Steps, current-step card internal padding |
| `p-8` | 32px | Top padding above first section below sticky header |
| `p-12` | 48px | Bottom content inset so last step clears nav bar |

Component-level spacing contract:
- Sticky header (exit + voice waveform + timer row + stop): **total height 64px when no timers active, 112px when timers active.** Timer chip row adds a fixed 48pt band.
- Step cards: **vertical gap between cards = 16px**; current-step card uses 24px internal padding, non-current cards use 16px.
- Ingredient rows: **16px vertical padding** (touch target — kitchen-friendly tap accuracy for wet/greasy fingers).
- Nav bar (Back / Repeat / Next) bottom-anchored: **72pt height** (deliberate Phase 19 deviation — see Exceptions).

**Exceptions (documented deviations):**
1. **Nav buttons at 72pt, not 44pt.** `StepNavButtons` Back/Repeat/Next use 72pt (not Phase 19's 44pt minimum). Rationale: cooking-hands accessibility — wet/greasy fingertips need a larger target. Tokens (color, radius, icon sizing) stay Phase-19-compliant; only height is overridden. Document this in 16-0X-PLAN.md and in a code-level comment on the component.
2. **Empty-state glyph size (56px raw)** from existing `EmptyState` is preserved; not added by this phase but inherited if a loading/error fallback renders.

## Typography

Phase 19 ships a 5-step type scale (`display`, `title`, `body`, `caption`, `label`).
**Cooking mode consumes exactly 4 of those 5 steps. `caption` (13pt) is NOT used
in cooking mode** — every element previously caption-sized has been reassigned
to either `body` (plain readable text) or `label` (small uppercase meta).
This keeps the in-cooking-screen type hierarchy bounded to 4 distinct sizes
(hitting the Dimension 4 typography cap) while still drawing every role from
the canonical Phase 19 scale.

**Weight contract: exactly 2 numeric weights — 400 (regular) and 700 (bold).**
The in-between Semibold (600) tier from Phase 19 is intentionally NOT used in
cooking mode. Visual differentiation between current-step (display 34pt) and
non-current (title 22pt) comes from size (34 vs 22), surface elevation, and
color — not weight. All emphasized roles (display, title, label, emphasized
body) collapse to 700.

| Role | Size | Weight | Line Height | Letter Spacing | Token |
|------|------|--------|-------------|----------------|-------|
| Display | 34pt | 700 | 41pt | -0.8 | `text-display` |
| Title | 22pt | 700 | 28pt | -0.3 | `text-title` |
| Body | 17pt | 400 | 22pt | 0 | `text-body` |
| Label | 11pt | 700 | 16pt | +0.6 | `text-label` (uppercase) |

Role assignments in cooking mode:

| Element | Role | Notes |
|---------|------|-------|
| Current step text (highlighted) | `display` (34pt/700) | Counter-distance readability is the primary constraint |
| Non-current step text | `title` (22pt/700) | Visible but subordinate; differentiation from current via size (22 vs 34), surface, and color — not weight |
| Recipe title (sticky header) | `title` (22pt/700) | Single-line, truncate with tail ellipsis |
| Step number label ("STEP 3 of 7") | `label` (11pt/700 uppercase) | Muted `text-text-tertiary` |
| Section headers ("INGREDIENTS", "STEPS") | `label` (11pt/700 uppercase) | `text-text-secondary` |
| Ingredient name | `body` (17pt/400) | Strikethrough + `text-text-tertiary` when checked |
| Ingredient quantity/unit prefix | `body` (17pt/700) | Bold override on the qty portion only — emphasis via weight bump to 700 |
| Timer chip countdown (e.g. "9m 23s") | `body` (17pt/700) | Bold for glance-read |
| Timer chip label (e.g. "RICE") | `label` (11pt/700 uppercase) | Above the countdown |
| Command-confirmation toast | `body` (17pt/700) | Single line, centered |
| Contextual tip body | `body` (17pt/400) | Retinted to `text-text-primary` on warning-tinted surface |
| "TIP" tip-badge label | `label` (11pt/700 uppercase) | `text-warning` tint |
| AskSheet question (recap of what the user asked) | `body` (17pt/400) | `text-text-secondary` — kept readable at counter distance |
| AskSheet answer | `body` (17pt/400) | `text-text-primary` |
| Nav button icons (Back/Repeat/Next) | SF Symbol size 28pt | `iconPropsForText('display')` returns 28; weight 700 |

**Note on 2-weight collapse:** Phase 19's base typography tokens include a
Semibold (600) step. Cooking mode intentionally drops that middle tier to stay
within the 2-weight Dimension 4 cap. Any element that would otherwise read
`600` (Title, Label, emphasized Body fragments like qty, Timer countdown, Toast
text, Nav icons) is bumped to `700` in this phase. Non-cooking screens across
the app still use the full Phase 19 weight range — the 2-weight collapse is
scoped to cooking mode components only.

**Note on reassignments from caption:** The contextual tip body and AskSheet
question recap were previously caption-role (13pt). Both are long-form plain
text the user reads hands-free at counter distance, so they promote to `body`
(17pt) — small, easy, and keeps the role count at 4. Nothing in cooking mode
should hit `caption` — if a design need surfaces that seems to want 13pt, route
it to `label` (if it's meta/uppercase) or `body` (if it's prose), or escalate
as a Phase 19.x amendment.

**Validation hook (per CONTEXT decision):** During UAT on a physical iPhone at
counter-height distance, confirm the `display` scale for the current step is
readable. If underscale, only the current-step role may upscale — all other
roles stay locked to the Phase 19 tokens. Document any adjustment in the plan's
visual-verification checkpoint.

**Never introduce a new font size or weight.** If a value is needed that's not
in the 4-role (+ 2-weight) cooking scale, the request is out of scope for Phase
16 and belongs in a Phase 19.x amendment.

## Color

Phase 19 semantic tokens are the authoritative palette. Cooking mode ships two
surface variants (light default + dark optional), both of which resolve to the
same semantic tokens — only the underlying CSS variable values swap.

### Light (default cream surface — `bg-bg` / #FAF7F2)

| Role | Hex | Token | Usage in cooking mode |
|------|-----|-------|-------|
| Dominant (60%) | #FAF7F2 | `bg-bg` | Full-screen background, non-current step cards |
| Secondary (30%) | #FFFFFF | `bg-surface` | Current-step card, ingredient rows, AskSheet |
| Accent (10%) | #C65D3A | `brand` | Current-step left-edge rail, timer chip background (@15% alpha), waveform mic fill, Stop button fill, nav-button active icon tint |
| Destructive | #DC2626 | `destructive` | Exit confirm destructive action, "End cooking session" |

### Dark (optional "Spotify Now Playing" theme — runtime toggle)

Activated by `cookingStore.darkMode` — persisted Zustand + AsyncStorage. The
dark palette lives in a `View`-level style override (not `@media
prefers-color-scheme` — scoped to cooking screen only per CONTEXT decision).

| Role | Hex | Token (dark override) | Usage |
|------|-----|-------|-------|
| Dominant (60%) | #141210 | `bg-bg` (dark) | Full-screen background |
| Secondary (30%) | #1E1B18 | `bg-surface` (dark) | Current-step card, ingredient rows |
| Accent (10%) | #C65D3A | `brand` (unchanged — tested against dark) | Same list as light; contrast holds |
| Text primary | #F5F0E8 | `text-text-primary` (dark) | Step text, ingredient names |
| Text secondary | #C4B7A4 | `text-text-secondary` (dark) | Step labels, muted copy |
| Border | #40372D | `border` (dark) | Card edges, ingredient divider |

Light/dark palette alignment matches the commented sketch in
`apps/mobile/src/global.css` lines 46-66 — promote those values into a live
cooking-scoped theme provider.

### Accent reserved for:

- Current-step card left-edge 4pt rail (solid `brand`)
- Current-step step-number label ("STEP 3 of 7") — `brand` tint
- Timer chip background at 15% brand alpha (`bg-brand/15`), border solid `brand`, text `brand-pressed`
- Listening-state waveform mic icon fill
- Voice-enabled idle pulse dot
- Stop TTS button icon fill + border
- Nav-button active-state icon tint (pressed)
- Command-confirmation toast left-edge accent strip

**Accent is NEVER used for:** nav-button backgrounds (tokens stay `bg-surface`
+ `border`), non-current step text, ingredient names, timer bar surrounds, exit
button, AskSheet chrome, contextual-tip body, sticky-header background, or the
ingredient-check icon (that is `success` — see below).

**Destructive tone reserved for:** exit-confirm destructive alert button only.
No destructive color in the main cooking UI — users exit via a benign X that
opens a confirm sheet.

**Semantic state tones (success/warning/info) reserved for:**
- `warning` (#D97706): contextual-tip "TIP" label + left rail + background tint at 10% (retints the existing amber-50/amber-200 hardcoded pair in `cook.tsx` line 245). **Must replace existing hardcoded amber classes** during Phase 16 sweep.
- `success`: ingredient-checked affordance. The check icon that appears when an ingredient is tapped uses `success` tone (not `brand`). Rationale: `brand` is already heavily reserved for the current-step rail, timer chip, mic fill, Stop button, nav-pressed tint, and toast accent — adding another brand surface would over-saturate the accent budget and weaken the current-step signal. `success` also semantically reads as "checked/done" which matches user intent better than the brand terracotta.
- `info`: not used in cooking mode.

## Copywriting Contract

All copy is sentence-case (except `label` role which is uppercase by token
convention). No em-dashes in UI copy per project-wide voice.

### Primary CTAs

| Element | Copy |
|---------|------|
| Enter cooking mode (from recipe detail, unchanged) | `Cook` |
| Advance to next step (voice confirm) | `Next step` (toast) |
| Go back one step (voice confirm) | `Previous step` (toast) |
| Repeat current step (voice confirm) | `Repeating` (toast) |
| Timer set (voice confirm) | `Timer set · {duration}` (e.g. `Timer set · 10 min`) |
| Stop TTS (visible text if label shown) | `Stop` |
| Stop TTS (accessibility label on icon-only button) | `Stop reading` — VoiceOver reads this aloud. "Stop" alone is ambiguous (stop what?); "Stop reading" scopes the action to the TTS narration specifically. |
| Exit cooking mode (top-left button) | `Exit` (visible text next to X icon — current pattern preserved) |
| Exit confirm — destructive | `End cooking session` (destructive red) |
| Exit confirm — cancel | `Keep cooking` |
| Dark mode toggle label (Settings > Cooking) | `Dark cooking mode` |
| Dark mode toggle subtitle | `Darker background while cooking. Matches Spotify's Now Playing feel.` |
| Voice toggle accessibility label | `Voice commands: {on|off}` |

### Empty / Edge States

| Element | Heading | Body |
|---------|---------|------|
| Recipe not found | `Recipe unavailable` | `We couldn't load this recipe. Go back and try again.` |
| Recipe loading | `Loading recipe...` | (no body; spinner only) |
| No ingredients in recipe (rare) | (no empty-state — ingredient section simply omits) | — |
| Voice recognition unavailable (permission denied) | `Voice commands need mic access` | `Enable microphone in Settings to cook hands-free.` |

### Voice Command Toast Copy (1.5s auto-dismiss, medium haptic)

Every recognized command confirms via toast, never TTS echo. Copy is
present-tense imperative (matches what just happened).

| Intent | Toast text |
|--------|------------|
| Next | `Next step` |
| Back | `Previous step` |
| Repeat | `Repeating` |
| Set timer | `Timer set · {N} min` |
| Cancel timer | `Timer canceled` |
| Show ingredients | `Ingredients` |
| Ask fall-through (routed to `/cooking/ask`) | no toast — AskSheet opens instead |

### Error States (in-cooking, non-blocking)

| Scenario | Copy |
|---------|------|
| `/cooking/ask` network failure | `Couldn't reach the kitchen assistant. Try again in a moment.` (inline in AskSheet) |
| STT transcript empty / no match | no visible copy; telemetry logs `unrecognized` event |
| TTS speech engine failure | silent fail; next step still advances |
| Timer expired (while app foregrounded) | TTS: `{label} timer done.` (existing Phase 9 behavior; unchanged) |

### Destructive Confirmations

| Action | Trigger | Sheet/Alert copy |
|--------|---------|------|
| Exit cooking mode mid-recipe | Tap top-left Exit | Title: `End cooking session?` / Body: `Your place in the recipe won't be saved.` / Destructive button: `End cooking session` / Cancel button: `Keep cooking` |

No other destructive actions in cooking mode. Timer cancel is reversible (user
can re-add) and does not require confirmation.

### Voice feedback principle

**Silent confirmation, loud announcement.** Recognized commands confirm with
toast + haptic only (no TTS echo — prevents the "I said Next, TTS says 'Moving
to step 3', step reads aloud" cascade). TTS is reserved for reading recipe
step content and timer-done announcements.

## Interaction Contract

### Layout structure (Claude.ai artifact pattern)

```
+------------------------------------+
| Sticky Header (64 or 112pt)        |
|  Exit X  |  Recipe title  | Waveform mic
|  [Timer chips row — when active]
|  [Stop TTS button — when TTS speaking]
+------------------------------------+
| ScrollView (vertical, full recipe) |
|                                    |
|  INGREDIENTS                       | ← label role, 11pt/700 uppercase
|  ☐ 2 cups rice                     | ← body role, tap to check, 16px vertical padding
|  ☐ 1 lb chicken breast             |
|  ...                               |
|                                    |
|  STEPS                             |
|                                    |
|  STEP 1 of 7                       | ← non-current, 22pt/700
|  Heat olive oil in a large pan...  |
|                                    |
|  STEP 2 of 7         (current) ◂▏  | ← highlighted card, 34pt/700
|  Add diced onions and cook until...| ← brand left rail, white surface,
|  [TIP: Low heat prevents burning.] |    elevated (shadow) in light mode
|                                    |
|  STEP 3 of 7                       |
|  Stir in garlic and...             |
|  ...                               |
|                                    |
|  (bottom inset 48px)               |
+------------------------------------+
| Bottom Nav Bar (72pt)              |
|  [  Back  ][ Repeat ][   Next   ]  | ← secondary variant, 72pt height
+------------------------------------+
```

### State transitions

| Trigger | Visual change | Animation |
|---------|--------------|-----------|
| Step advance (next / voice / intent router) | Current-step highlight shifts one card down; scroll animates previous-current off-screen or to top, new-current centered in viewport | `ScrollView.scrollTo({ y, animated: true })` — 400ms iOS default; use Reanimated if jank observed |
| Step back | Mirror of advance, scroll direction reversed | Same |
| Repeat | No scroll; current-step card pulse (brand rail thickens 4pt→8pt→4pt) | 300ms Reanimated pulse |
| Ingredient tap | Row transitions to strike-through + tertiary text + `success`-tinted check icon | 150ms opacity + text-decoration |
| Voice listening → speaking | Waveform bars animate to amplitude | Reanimated `withRepeat` loop; amplitude from STT partial-result callback |
| Voice idle → listening | Static dot → waveform (smooth 200ms crossfade) | Reanimated `withTiming` |
| TTS starts | Stop button slides in from sticky-header right edge | 200ms slide + fade |
| TTS ends | Stop button slides out | 200ms slide + fade |
| Toast appears | Fade + 4pt slide-down from below sticky header | 200ms fade-in, 1.3s hold, 200ms fade-out (matches existing `useToast` timing) |
| Timer chip at T-10s | Light haptic + chip background transitions to `warning` @20% alpha | 300ms color interpolation; haptic fires once at T=10.0s |
| Timer expires | Chip removed; TTS announcement `{label} timer done.` | 200ms chip fade-out |
| Dark-mode toggle | Full-screen background + surface + text tokens cross-fade | 250ms color interpolation on root `View` style; no flash |

### Gesture contract

- **Vertical scroll:** native `ScrollView` behavior. No pull-to-refresh.
- **Horizontal swipe on step card:** reserved for future (Phase 16 does NOT implement). Voice / nav buttons are the only step-advance inputs.
- **Long-press anywhere on cooking screen:** optional dark-mode toggle per CONTEXT decision. If implemented, 600ms press with light haptic on engage. Settings toggle is the primary entry; long-press is the secondary.
- **Tap Exit X:** opens iOS action sheet with destructive "End cooking session" + cancel. No direct dismiss.
- **`gestureEnabled: false`** on the screen (Phase 9 convention preserved) — no swipe-to-pop navigation.

### Haptic contract (via `expo-haptics`)

| Event | Feedback |
|-------|----------|
| Voice command recognized (Next/Back/Repeat/Timer) | `Haptics.ImpactFeedbackStyle.Medium` |
| Ingredient tap-to-check | `Haptics.ImpactFeedbackStyle.Light` |
| Step card long-press (dark-mode toggle, if shipped) | `Haptics.ImpactFeedbackStyle.Light` |
| Timer at T-10s warning | `Haptics.ImpactFeedbackStyle.Light` (once) |
| Timer expires | `Haptics.NotificationFeedbackType.Success` |
| Stop TTS button tapped | `Haptics.ImpactFeedbackStyle.Medium` |
| Exit confirm destructive tap | `Haptics.NotificationFeedbackType.Warning` |

Works when phone is on silent mode (haptics are independent of ringer).

### Accessibility

- `accessibilityLabel` on icon-only controls:
  - Exit X → `Exit cooking`
  - Voice-toggle waveform → `Voice commands: {on|off}`
  - Stop TTS → `Stop reading` (scoped verb; "Stop" alone was ambiguous)
  - Back/Repeat/Next nav buttons (even though nav buttons show text — SF Symbol + label both contribute)
- `accessibilityRole="button"` on all Pressables.
- `accessibilityState={{ selected: true }}` on the current step card.
- `accessibilityLiveRegion="polite"` on the toast surface (announces recognized commands to VoiceOver users).
- Ingredient checkboxes: `accessibilityRole="checkbox"` + `accessibilityState={{ checked }}`.
- Screen stays awake via `useKeepAwake()` (unchanged Phase 9 behavior).
- Minimum contrast: all text passes WCAG AA 4.5:1 at body size; verified for both light and dark palettes via `tokens.test.ts` extension.
