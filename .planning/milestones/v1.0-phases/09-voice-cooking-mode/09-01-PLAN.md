  <behavior>
    cookingStore (Zustand):
    - Initial state: recipe=null, stepIndex=0, voiceEnabled=true, ttsEnabled=true, listening=false, timers=[], lastAssistantAnswer=null
    - enter(recipe): sets recipe + stepIndex=0
    - exit(): resets recipe/stepIndex/timers/listening
    - next(): stepIndex clamps at steps.length-1 (never exceeds)
    - back(): stepIndex clamps at 0 (never negative)
    - repeat(): no state change (triggers re-read via effect key downstream) — test asserts stepIndex unchanged but call is observable
    - addTimer(ms): pushes Timer { id, label: "`${round(ms/60000)} min`", endsAt, remainingMs }; id is non-empty string
    - removeTimer(id): filters timers
    - setListening(bool): toggles
    - setAssistantAnswer(str): stores

    Tests cover each action path including boundary clamps (next past last step stays at last; back from 0 stays 0) and addTimer shape.
  </behavior>
  <action>
    Create apps/mobile/src/types/cooking.ts:
    ```ts
    export type CookingIntent =
      | { type: 'next' }
      | { type: 'back' }
      | { type: 'repeat' }
      | { type: 'timer'; ms: number }
      | { type: 'pause' }
      | { type: 'resume' }
      | { type: 'ask'; question: string };

    export interface Timer {
      id: string;
      label: string;
      endsAt: number;      // epoch ms
      remainingMs: number;
    }

    export interface CookingState {
      recipe: import('./recipe').Recipe | null;
      stepIndex: number;
      voiceEnabled: boolean;
      ttsEnabled: boolean;
      listening: boolean;
      timers: Timer[];
      lastAssistantAnswer: string | null;
    }
    ```

Use research Pattern — see 09-RESEARCH.md "cookingStore shape" section. For Timer.id use `Math.random().toString(36).slice(2)` (crypto.randomUUID may not exist in RN runtime reliably — avoid).
