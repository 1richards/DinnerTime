Create the migration per research "Data Model" section with these exact elements:

1. Three tables:
   - `shopping_lists` (id UUID PK, profile_id FK CASCADE, meal_plan_id FK SET NULL, title TEXT, generated_at, created_at, updated_at)
   - `shopping_list_items` (id UUID PK, shopping_list_id FK CASCADE, name, normalized_name, quantity NUMERIC, unit TEXT nullable, category TEXT default 'other', sources JSONB default '[]', checked BOOLEAN default FALSE, user_added BOOLEAN default FALSE, created_at)
   - `shopping_orders` (id UUID PK, profile_id FK CASCADE, shopping_list_id FK SET NULL, items_snapshot JSONB NOT NULL, instacart_url TEXT NOT NULL, expires_at TIMESTAMPTZ nullable, placed_at)

2. Indexes:
   - idx_shopping_lists_profile ON shopping_lists(profile_id, created_at DESC)
   - idx_shopping_list_items_list ON shopping_list_items(shopping_list_id)
   - idx_shopping_orders_profile ON shopping_orders(profile_id, placed_at DESC)

3. updated_at trigger on shopping_lists (mirror Phase 7 pattern: BEFORE UPDATE trigger calling a set_updated_at() function — reuse if it already exists in earlier migration; else create).

4. RLS policies (mirror Phase 7 exactly):
   - Enable RLS on all three tables
   - shopping_lists: SELECT/INSERT/UPDATE/DELETE WHERE profile_id = auth.uid()
   - shopping_list_items: use EXISTS subquery through shopping_lists.profile_id = auth.uid() (the pattern established in 07-01 for meal_plan_entries)
   - shopping_orders: SELECT/INSERT/UPDATE/DELETE WHERE profile_id = auth.uid()

Avoid: Do NOT create a shared ingredient_categories cache table in this migration (deferred — Plan 03 stores categories inline on shopping_list_items.category per research Pitfall 5 resolution).
