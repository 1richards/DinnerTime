## Phases

### Phase 26: Missing-ingredient indicators on recipe ingredient lists

**Goal:** On every surface that lists a recipe's ingredients (Recipe Box detail, Discover preview, Plan day modal, Cooking mode), show which ingredients the user does not have in their pantry, and let them tap a missing ingredient to add it to the shopping list inline. Reuses the bidirectional substring + staples heuristic from `computePantryReady` and mirrors the trailing-chip pattern from `PantryItemCard.tsx`.

**Plans:** 1 plan, 3 atomic tasks

Plans:
- [x] 01-PLAN.md — Helper + PreviewSheet wiring (3 surfaces) + ScrollableRecipe (cooking mode) + tests

- Extended `ScaledIngredientList` with optional trailing missing-indicator + tap handler; back-compat preserved.
- PreviewSheet (`discover.tsx`) wired with `usePantryStore` (filtered to `status === 'available'`) + `useShoppingStore.addItem` + `Alert` rollback. Single wiring covers Recipe Box detail, Discover preview, AND Plan day modal because all three mount the same component.

## Milestone Summary

**Decimal Phases:** None.

**Key Decisions (locked in CONTEXT.md):**
- Visual: trailing `cart.badge.plus` → `cart.fill` icon on missing rows; ingredient text stays full color (no strikethrough)
- Coverage: all four surfaces (Recipe Box / Discover / Plan day / Cooking mode)
- Match logic: reuse `computePantryReady`'s bidirectional substring + skip `PANTRY_STAPLES`; filter pantry to `status === 'available'`
- Tap action: optimistic add to shopping list via `useShoppingStore.addItem`; `Alert` on failure with icon rollback

**Issues Resolved:**
- "Which recipe ingredients are we missing from the pantry?" was previously only computed at the day-chip level (`pantry_ready` boolean). Per-ingredient visibility was missing.
- Inconsistent visual vocabulary: pantry rows had an "In cart" chip (from the trifecta `4a61494`) but recipe ingredient rows had no equivalent affordance.

**Issues Deferred:**
- Per-card pantry coverage on the Recipe Box GRID (different scope, would need card-layout work) — deferred to future milestone
- Aggregate "Add all missing to cart" CTA — bigger UX decision (placement, batching semantics, undo) — deferred
- Quantity-aware coverage (pantry has 1 lb chicken, recipe needs 2 lb) — current heuristic is presence-only, server-side `subtractPantry` handles quantity math at shopping-list generation time — deferred
- Physical-iPhone UAT (7 scenarios) — explicit user deferral during autonomous run; documented in v1.0.1 audit

**Technical Debt Incurred:**
- Nyquist `VALIDATION.md` was not generated for Phase 26 — autonomous workflow skipped that step in the interest of momentum (CONTEXT.md provides equivalent decision traceability; vitest coverage at 29/29 is comprehensive). Tracked in `v1.0.1-MILESTONE-AUDIT.md`.
