<objective>
Cut `/cooking/ask` p95 TTS-first-word from ~2-3s to <1.5s by streaming Claude's response via Server-Sent Events and starting TTS on first sentence boundary. Preserves Claude Sonnet 4 + max_tokens:300 brevity.

Purpose: The CONTEXT latency target (p95 < 1.5s from user-finished-speaking to TTS-first-word) is unachievable with non-streaming — the full response arrives before TTS can start. SSE streaming decouples text-arrival from TTS-playback.
Output: Server `/ask-stream` SSE endpoint + mobile `streamAsk` client, both green against Wave 0 tests. Sentence-chunking for TTS is wired in Wave 3 (16-06); this plan just delivers the streaming transport.
</objective>
