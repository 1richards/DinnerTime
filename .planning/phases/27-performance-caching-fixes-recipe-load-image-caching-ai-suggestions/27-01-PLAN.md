<objective>
Make generated hero images durable: persist the resolved URL back to `recipes.image_url` so a
saved recipe never re-requests `POST /generate-image` on a later cold start, new device, or
AsyncStorage clear. This is Decision 1 (Image P0, HIGHEST IMPACT) — the dominant root cause in
`.planning/debug/perf-recipe-load-image-caching.md`.

Purpose: After first generation, `recipe.image_url` is set → the mobile `RecipeCard` passes
`skip=true` to `useGeneratedRecipeImage` → zero generate-image requests on subsequent cold starts.
Output: An extended `POST /generate-image` handler + tests. Server-only; no migration.
</objective>
