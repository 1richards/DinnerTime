  <files>packages/server/src/routes/shopping.ts</files>
  <action>
Replace the existing stub `packages/server/src/routes/shopping.ts` with a full Hono app exporting routes per research "API Surface" table:

```
POST   /generate                  { meal_plan_id } → ShoppingList with items
GET    /current                   → most recent ShoppingList with items (null if none)
GET    /:id                       → specific list
POST   /items                     { shopping_list_id, name, quantity?, unit? } → adds user_added item
PATCH  /items/:id                 { checked?, quantity?, name?, unit? } → updated item
DELETE /items/:id                 → 204
POST   /:id/order                 → calls Instacart, persists order, returns {url, order_id}
GET    /orders                    → past orders for profile
POST   /orders/:id/reorder        → NEW list seeded from items_snapshot
POST   /orders/:id/variations     → Claude Haiku swap suggestions
```

Key implementation details:

1. **Auth middleware**: reuse the same `requireAuth` or equivalent from meal-plans.ts; grab `profile_id` from `c.var.user.id`.

2. **/generate flow**:
   - Fetch meal_plan by id scoped to profile_id → 404 if not found
   - Fetch meal_plan_entries for that plan
   - Fetch pantry_items for profile_id
   - `const needed = consolidateIngredients(entries)`
   - `const remaining = subtractPantry(needed, pantry)`
   - `const categories = await classifyItems(remaining)` (keyed by normalizedName)
   - Insert shopping_lists row (title: `DinnerTime — week of ${meal_plan.week_start}`)
   - Bulk insert shopping_list_items with category from the classify map
   - Return joined list + items

3. **/:id/order flow** (per research Pitfall 4):
   - Fetch list + items scoped to profile_id
   - Filter out checked items (only order unchecked)
   - Map to InstacartLineItem[]: `{ name, line_item_measurements: quantity && unit ? [{quantity, unit}] : undefined }`
   - `const client = getInstacartClient()`
   - `const { products_link_url } = await client.createShoppingListPage({ title: list.title, line_items, expires_in: 30, partner_linkback_url: 'dinnertime://shopping/done' })`
   - Insert shopping_orders row with items_snapshot (the InstacartLineItem array), instacart_url, expires_at = now() + 30 days
   - Return `{ url: products_link_url, order_id }`

4. **/orders/:id/reorder flow** (critical: NEVER replay old URL per Pitfall 4):
   - Fetch order scoped to profile_id
   - Insert a new shopping_lists row with title like `Reorder — ${order.placed_at}`
   - Insert shopping_list_items from items_snapshot (mark user_added=false, category='other' since snapshot doesn't carry category — acceptable; user can re-categorize by running variations or editing)
   - Return the new list with items
   - Do NOT re-classify with Haiku in this path (keep reorder fast; category can default to 'other' from snapshot)

5. **/orders/:id/variations flow**:
   - Fetch order items_snapshot
   - Convert to ConsolidatedItem[] minimal shape: `{ name, normalizedName: normalizeIngredientName(name), quantity: measurement?.quantity ?? 1, unit: measurement?.unit ?? null, sources: [] }`
   - Call `suggestVariations(items)` → return array

6. **Error mapping** (follow Phase 7 convention: service error.code → HTTP):
   - Missing meal_plan → 404 with `{ code: 'MEAL_PLAN_NOT_FOUND' }`
   - Empty meal_plan_entries → 400 `{ code: 'EMPTY_PLAN' }`
   - Instacart client throw → 502 `{ code: 'INSTACART_ERROR', message: err.message }`
   - Generic catch → 500

7. **PATCH /items/:id**: use 4-field whitelist (checked, quantity, name, unit) — drop unknown keys silently (Phase 6-02 convention).

8. **Route registration**: maintain existing import in `packages/server/src/server.ts` (stub is already mounted at `/api/v1/shopping` — verify, do not re-mount).

Avoid:
- Do NOT import services inside loops; import once at top.
- Do NOT store the Instacart URL and replay it on reorder (Pitfall 4).
- Do NOT block /generate on classifyItems errors — on failure, default category to 'other' for all items and log a warning (graceful degradation).
- Do NOT call Haiku synchronously during /order — only during /generate and /variations.
- Do NOT forget `profile_id` scoping on EVERY query (RLS is a safety net, not the primary scope).
