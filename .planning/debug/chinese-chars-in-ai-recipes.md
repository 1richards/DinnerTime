## Resolution

root_cause: All recipe-text generation routes to Gemini Flash preview models. The GeminiAdapter issues structured calls with no temperature override (default ~1.0) and no degeneration/output validation, so the model's CJK repetition-loop output (调整/碎/块/条) is returned verbatim and stored. Confirmed Gemini, not Anthropic.
fix: (A) PREVENTION — lower sampling temperature on structured Gemini calls + add a shared sanitization/validation guard (detects CJK/non-Latin contamination in English recipe fields, strips trailing/embedded CJK tokens) applied at the parse boundary of every Gemini recipe path. (B) CLEANUP — admin POST /recipes/sanitize-cjk sweep mirroring seed-baseline-backfill to strip CJK from already-stored ingredient/step/title text across all users.
verification: Unit: 11 new sanitizer tests verify the exact reported strings (碎/块/调整/条) are stripped and clean text is byte-identical. Regression: recipeParser + recipeDiscovery + geminiAdapter existing tests still pass (48/48). Build: zero new type errors (63 pre-existing Hono c.get() errors unchanged on baseline). Pending: human verify a freshly generated recipe is clean + run the sanitize-cjk sweep against the live DB.
